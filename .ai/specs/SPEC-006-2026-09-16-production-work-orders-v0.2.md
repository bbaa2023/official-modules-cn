# SPEC-006 — 生产工单 V0.2：生产报工与 AI 生产分析

## 目标

在 V0.1 工单主数据与状态机基础上，进入真正的生产执行阶段：让工单能够记录实际生产进度，并让 AI 基于生产数据进行查询、分析和风险提示。

## V0.2 范围

### 1. 生产报工

- 工单完工数量录入
- 工序报工
- 工序完成状态
- 实际完成数量校验
- 防止完工数量超过计划数量
- 工单进度自动计算
- 计划数量 / 完成数量 / 剩余数量
- 进度百分比

### 2. 工序执行

- 工序开始 / 暂停 / 完成
- 工序实际完成数量
- 工序实际工时
- 工序执行状态
- 工序与工作中心的关联保持 ID 引用

### 3. AI 生产分析

新增只读 AI 能力：

- 查询延期工单
- 查询低进度工单
- 查询即将到期工单
- 查询生产中工单
- 汇总生产进度
- 分析工单风险
- 根据交期、计划数量、完成数量生成结构化风险说明

AI 分析默认只读，不直接修改生产数据。

### 4. AI 生产执行

保留 Open Mercato mutation / approval 机制：

- AI 可以提出报工或状态变更建议
- 涉及生产数据写入时必须进入确认/审批流程
- AI 不得绕过 Command 层直接写数据库

## 数据模型增量

根据实际代码审查结果决定是否增加独立报工实体；优先避免破坏 V0.1 数据模型。

候选字段：

- reported_quantity
- actual_minutes
- execution_status
- started_at
- completed_at
- operator_id（仅在平台现有用户模型能够稳定引用时增加）

跨模块对象继续使用 ID / string 引用，不建立不必要的 ORM 直接关系。

## API

计划增加：

- 工单报工 API
- 工序报工 API
- 工单进度 API
- 生产分析 API / AI tool

所有写操作继续经过 Command、租户/组织隔离和 RBAC。

## UI

- 工单详情页增加生产执行区
- 完工数量录入
- 工序报工操作
- 进度仪表 / 进度条
- 工序执行状态
- 风险提示区域
- 生产分析入口

## RBAC

根据现有 RBAC 继续细分：

- production_work_orders.report
- production_work_orders.execute
- production_work_orders.analyze

最终 feature 命名以仓库现有权限体系为准，避免重复创建语义相近权限。

## 明确不进入 V0.2

- BOM
- MRP
- 高级产能排程
- 成本核算
- 库存自动扣料
- 采购联动
- 财务联动
- 复杂 MES 设备采集

这些进入后续生产计划 / MRP 阶段。

## 验收标准

1. 一个工单可以记录实际完成数量。
2. 完工数量不能超过计划数量。
3. 工序可以记录执行进度。
4. 工单总体进度可以自动计算。
5. 可以查询延期、低进度和即将到期工单。
6. AI 可以对生产状态进行只读分析。
7. AI 涉及写入时必须经过确认/审批链路。
8. 所有数据继续满足 tenant / organization 隔离。
9. 不修改 Open Mercato core packages。
10. CI 完成 build、typecheck、test、i18n 检查后再考虑将 PR 从 Draft 转为 Ready。
